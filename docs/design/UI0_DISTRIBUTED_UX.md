# UI-0 · 鸿蒙原生互联（Distributed UX）

> 本文件给出协同任务流程与接口需求。**所有 Kit/API 的设备条件、API 26 支持与权限，
> 本轮均未在真机验证**；不得把本文当作「已实现」或「已验证可用」。

## 1. 目标场景（按价值排序）

| 场景 | 用户价值 | 依赖能力 | 状态 |
|---|---|---|---|
| A. 拍摄方案分享（图片/文本） | 把某天某机位的窗口方案发给同伴 | `ShareKit` / 系统分享（或已有的 PNG/CSV 导出 + 分享） | 导出已实现（DEVICE 部分验证），**分享入口未实现** |
| B. 应用接续（手机→平板继续编辑） | 在设备间无缝继续规划 | `DistributedMissionManager`/接续能力（需核实 API 26 与设备条件） | **NOT_RUN**（未验证） |
| C. 双设备协同勘景（一台看罗盘、一台看曲线） | 现场分工 | 分布式软总线/跨设备数据同步 | **NOT_RUN**（未验证） |
| D. 机位与计划跨端同步 | 多设备数据一致 | 分布式数据对象/云同步（涉及账号与隐私） | **NOT_RUN**（本轮不实现） |

## 2. 交互流程草案（B：应用接续）

1. 手机端在 `PlannerPage` 编辑态时，若系统提示可接续，显示一次性「在平板上继续」入口；
2. 接续必须携带最小状态：`placeId`、`selectedUtc`、`pickedDate`、表单字段、`editId`；
3. 接续完成后**不得**重算 UTC（沿用 `selectedUtc`），也不得自动保存；
4. 任一端保存后，另一端显示「已被更新」提示，避免并发覆盖；
5. 失败/超时（>10s）→ 静默降级为「本地继续编辑」，不阻塞用户。

## 3. 数据一致性约束

- 计划以 `id` 为唯一键；接续/同步只能是「带版本号的条件写入」，禁止盲写；
- 机位以坐标 + `tzId` 快照保存（现状已如此），跨端不依赖机位是否存在于对方设备；
- 冲突策略：最后保存者胜，但必须先提示差异（时间/机位/清单三项之一变化即提示）。

## 4. 权限与隐私

- 分享仅由用户主动触发，禁止后台自动上传；
- 分享的图片/CSV 不得包含精确住址等无关信息；坐标属于用户主动填写的机位数据，导出前提示；
- 跨端同步若引入账号体系，需要单独评估隐私合规与账号注销路径（本轮不做）。

## 5. 待核实清单（实现前必须完成）

1. API 26 是否提供接续能力的稳定 Kit，当前设备（MIA-AL00）是否支持；
2. 分享图片是否需要 `ohos.permission.INTERNET` 或由系统分享面板代理（现状：应用无网络权限，倾向系统分享）；
3. 跨设备发现所需的权限与用户在 `Settings` 的可见开关；
4. 自由窗口/折叠设备上接续的目标窗口形态。
