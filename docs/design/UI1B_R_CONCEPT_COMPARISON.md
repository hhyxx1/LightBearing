# UI-1B-R · 三套方案对比与推荐

> 三套方案：`design/ui1b-r/concept-a|b|c.html`，截图 `design/ui1b-r/shots/concept-*-compact.png`，
> 并排对照 `design/ui1b-r/comparison.html` / `shots/comparison.png`。
> 三套**均未实现到生产代码**；本文件只给推荐，不代替用户决策。

## 1. 共同点（三套都遵守的底线）

- 数据口径不变：方位/高度/时间/时段全部来自 SolarCalc + Timeline + lightWindows；
- 时段长度按真实比例绘制，不为好看放大；极短窗口用标签/「下一窗口」卡片提高可辨识度；
- 每个关键事实只有一个主展示位（日出日落只在明细/时间轴出现一次）；
- 深色为主设计，浅色可按同一层级换算；
- 主按钮 48vp，底部 Tab 64vp，状态用「文字 + 颜色」双通道。

## 2. 结构差异（不是换色）

| 维度 | A · Precision Instrument | B · Solar Timeline | C · Field Photographer |
|---|---|---|---|
| 首屏第一眼 | 方位/高度大读数 + 仪表曲线 | 全天时间轴（分段带 + 下一窗口） | 结论卡「现在适合拍摄」 |
| 信息组织 | 仪表 → 读数三列 → 明细行 → 操作 | 下一窗口 → 全天分布 → 窗口列表 → 操作 | 结论 → 下一窗口 → 折叠细节 → 主 CTA |
| 时间表达 | 全天细条 + 刻度 | 主视觉分段带（夜/微光/黄金/蓝调真实比例） | 只给「还有约 48 分钟」+ 下一窗口 |
| 图表地位 | 高（是核心） | 高（曲线缩略 + 分段带） | 低（曲线移到二级页） |
| 适合的用户 | 想精确判断方位/高度的建筑/风光摄影 | 以「今天什么时候出门」为核心的用户 | 现场快速决策、需要「能不能拍」结论的用户 |
| 扩展到大屏 | **最自然**（读数区可拆双栏） | 自然（时间轴横向延展） | 一般（结论卡在大屏会空） |

## 3. 十项视觉验收对比

见 `comparison.html` 的表格（同内容），要点：

1. **视觉重心**：A=数据、B=时间轴、C=结论，三者都明确，不存在「标题压住内容」；
2. **专业定位**：A 最强（专业仪表），B 中强（时间规划），C 中（现场助手）；
3. **信息重复**：B 最低（分段带替代文字列表）；C 略重（结论与下一窗口部分重叠，已用不同措辞）；
4. **主次层级**：A 三层、B 三层、C 渐进披露最好；
5. **首屏判断**：三套都能在首屏回答「太阳在哪 / 什么阶段 / 下一次何时」，
   A 额外给出方位与高度的精确值；
6. **读数可读性**：A 最强（等宽数字、三列对齐、UTC 偏移常驻）；
7. **图表语义**：A/B 都有真实地平线、刻度与真实时段；C 把图表降级到二级页（取舍明确）；
8. **交互入口**：C 的主 CTA 最易发现；B 的时间轴本身可点；A 靠底部三按钮；
9. **深浅色**：三套都只依赖面/线/两色强调，换算到浅色风险一致；
10. **多设备基础**：A > B > C。

## 4. 推荐

**推荐 A（Precision Instrument）作为主方向，吸收 B 的分段带与 C 的「下一窗口」措辞。**

理由：

1. LightBearing 的差异点是**精确太阳数据**，A 把读数放在第一视觉位，最符合「专业摄影工具」定位；
2. B 的分段带是 A 全天细条的升级版：可在 A 中把细条换成**真实的日段带**（夜/微光/黄金/蓝调），
   既保留 A 的密度，又解决「细条辨识度不足」；
3. C 的「现在适合拍摄 / 还有约 N 分钟」是**极好的首屏语义**，建议以一句话放在 A 的仪表上方，
   而不是单独做一张大结论卡；
4. A 的双栏扩展最省事：宽屏时左仪表 + 右明细，不需要重排信息架构。

**不建议**把 C 直接作为首页：它把曲线降到二级页，弱化了产品最核心的专业数据表达。
