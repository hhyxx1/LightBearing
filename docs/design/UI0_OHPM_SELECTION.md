# UI-0 · OHPM 组件选型（研究与建议）

> **重要声明**：本轮**没有**访问 OHPM 仓库、没有安装任何依赖、没有在 API 26 真机上验证下列组件。
> 因此「版本 / 许可 / 兼容性 / 包体积」等字段全部标记 **UNVERIFIED**，不得作为实施依据。
> 本文件给出的是评估标准、候选清单与建议路径；实际选型必须由后续轮次逐项核实后再落地。

## 1. 评估维度（每项必须给出证据）

| 维度 | 判定方式 |
|---|---|
| API 26 兼容 | 在目标设备（MIA-AL00 / HarmonyOS 7）跑通最小 demo，记录报错与降级 |
| 维护活跃度 | 仓库提交时间、issue 响应、是否有 API 26 适配说明 |
| 许可 | LICENSE 文件类型，是否允许商用/闭源分发 |
| 体积 | 引入后 HAP 增量（当前基线 HAP ≈ 2.3 MB） |
| 性能 | 首屏与长列表帧率、内存增量（与纯 ArkUI 实现对比） |
| 可替代性 | 是否 200 行内可用纯 ArkUI 实现同等效果 |
| 风险 | 是否引入权限、网络、原生 so、后台能力 |

## 2. 候选清单（状态：UNVERIFIED）

| 组件 | 拟解决 | 纯 ArkUI 替代方案 | 初步建议 |
|---|---|---|---|
| `@ohos/mpchart` | 太阳高度/多日对照图表 | 已自研 `Charts.ets`（SunPathChart / CompareChart） | **不引入**：现有自研图表已覆盖需求，引入会带来双套图表体系 |
| `@ohos/lottie` | 罗盘/太阳动效 | ArkUI 原生 `animateTo` + Canvas | **暂不引入**；若 UI-1 需要复杂矢量动效，先做单点评估 |
| `@ohos/lottie-turbo` | 同上（高性能版） | 同上 | 同上；两者只评估其一 |
| `@pura/harmony-dialog` | 统一弹窗 | 已有 `Widgets.Dialogs` 封装 | **不引入**：自研弹窗已统一 |
| `@pura/harmony-utils` | 工具集合 | 现有 `TimeUtil/CsvCodec/ExportService` | **不引入**：避免引入大而全工具库，且与本项目时间/时区逻辑无协同 |
| `@ohos/rebound` | 弹性动画 | ArkUI `springCurve` | **不引入**：原生动效已够用 |
| `@ohos/svg` | SVG 图标 | 现有线性图标（组件内绘制） | **暂不引入**；若 UI-1 需要复杂插画再评估 |

## 3. 结论与路径

1. **原生优先**：本轮所有候选都不建议立即引入；现有自研组件（图表、弹窗、图标、工具）已覆盖需求；
2. 若 UI-1 出现「原生无法实现」的具体缺口（例如复杂路径动画或大数据量图表交互），
   再按 §1 的维度做**单组件**评估，并在真机记录 HAP 增量与帧率；
3. 禁止一次性安装全部候选依赖；每次引入必须附：版本、许可、API 26 实测、体积增量、回滚方案。
