# 02C-2 · 反向寻光搜索内核正确性修复

> 基准 `ad6d849`，工作分支 `fix/core-quality-audit`。本轮只改搜索内核与其兼容包装；
> 未改动 SolarCalc 公式、LocalTimeResolver/TimeUtil 解析、页面结构、数据库与 main。
> 跨日 Top-K、取消粒度、调度与 UI 留给 2C-3。

## 1. 最终算法设计

新增 `services/ReverseSearchKernel.ets` 与 `model/ShootWindow.ets`，生产入口：

```text
ReverseSearch.searchWindowsInRanges(goal, th, ranges, stats) → ShootWindow[]
ReverseSearch.searchInRanges(...) → Candidate[]        // 兼容包装：每窗口一个 Candidate
```

内核流程（对每个 `[startUtc, endUtc)`）：

1. **自适应区间三态分类** `collect(a,b,depth)`：
   - 采样 `a`、`mid`、`b-1` 三个点，用**显式的变化率上界**构造保守包络：
     `altMargin = 0.0045 °/s × w/2`，`azMargin = 0.05 °/s × w/2`（仅在方位连续时适用）；
   - 若**任何采样点都不可能有效** → 整段可证无效 → 剪枝；
   - 若**所有采样点都必然有效** → 整段可证有效 → 直接收下一整段（长窗口不会被逐点展开）；
   - 否则二分继续细分。
   - 最近采样点距区间内任一点不超过 `w/4`，而 margin 按 `w/2` 估计，因此上述两个结论是保守的。
2. **1 秒叶子判定**：细分到 `≤1000 ms` 时逐点用**两个独立容差**（外加 `daylightOnly` 的严格不等式）判定。
3. **窗口构造**：相邻有效跨度相接/重叠即同一窗口；中间存在无效时间就分离——**不做任何基于 bestUtc 距离的合并**。
4. **窗口内求最优**：先按 ≤200 点取样，再黄金分割细化，最后用双容差**强校验**；任一不满足则该窗口不输出。
   这样「cost 最小但单轴越界」的点不会被选中（修 D2）。
5. **数值滞后处理**：达到 `MAX_DEPTH=18` 仍无法判定的区间退化为 1 秒扫描，并计入
   `KernelStats.unresolvedIntervals`（诚实记录近似性）。

窗口模型 `ShootWindow`：`startUtc / endUtc / bestUtc / bestAzimuth / bestAltitude / bestAzError /
bestAltError / phase / valid / degenerate`，全部 UTC 毫秒，**不使用负数哨兵**，1970 年前负时间戳合法。
退化命中（切点）用 `degenerate=true` 且 `endUtc = startUtc + 1` 表达，不会变成非法零长度区间。

## 2. 为什么能发现旧版的 32 秒窗口

旧版只有在「5 分钟采样点恰好落进窗口」时才进入细化；32 秒窗口落在 `16:00:00` 与 `16:05:00` 之间，
两点都在容差外，于是整窗漏报。

新内核不依赖采样点命中：区间分类只在**能用速率上界证明整段无效**时才剪枝，
32 秒窗口所在的那 5 分钟区间两侧采样点都「可能有效」（包络覆盖 ±几个角秒），因此被继续二分，
最终在 1 秒叶子上判定为有效并合成窗口。同理，「同一区间内两次穿越」「切点」「两个 10 秒间隔的独立窗口」
都不会因为「端点符号相同」而被剪掉——因为剪枝依据是**包络**而不是端点符号。

## 3. 分类/排除依据与适用条件

| 依据 | 说明 | 适用条件 |
|---|---|---|
| 高度变化率上界 0.0045 °/s | 太阳高度随时间的变化不会超过该值 | 全天 |
| 方位变化率上界 0.05 °/s | 仅在方位**连续**时使用 | 区间内相邻采样点 \|Δaz\| ≤ 30°，且高度 < 80° |
| 方位不连续/近天顶 | 放弃上界 → 必然返回「继续细分」 | 高纬或接近天顶 |
| `daylightOnly` | 高度 `> -0.833°` 是**严格**不等式，用 `daySlack > 0` 单独判定 | 开启过滤时 |

不满足上界条件时算法**只会更保守**（继续细分），不会错误剪枝——这是本轮的关键正确性保证。

## 4. 阈值边界求解方式

本轮采用「1 秒叶子 + 区间聚合」得到边界，边界精度 = 1 秒（`RESOLUTION_MS`）。
没有单独对四个阈值函数做二分，原因：三态分类已经把「确定有效/确定无效/需细分」判定清楚，
边界误差由叶子宽度直接限定在 1 秒；二分留给 2C-3（可与取消粒度一起做增量式求根）。
高度阈值使用**有符号物理差**：`altSlack = altTol - |alt - target|`、`daySlack = alt + 0.833`，
避免 `altErr + tol` 这类不产生零点的写法；方位用 `SolarCalc.angularDistance`（环形距离）保证 0/360 正确。

## 5. 窗口构造与去重规则

- 同一连续有效窗口只出现一次；
- 两个窗口只要中间存在无效时间就保持独立，**哪怕只隔 10 秒**（合成轨迹用例实测 gap ≈ 10 s 仍是 2 个窗口）；
- 边界恰好相接（`s <= prevEnd`）视为同一窗口的延续；
- 逐日调用天然遵守真实本地日边界（23/25/23.5/24.5 小时），不引入 24 小时常量；
- `searchInRanges` 的候选数**等于**窗口数，窗口之间互不重叠（用例断言）。

## 8. 错误合并检测方法

- **新内核侧**（已实现，在测试层）：候选数 == 窗口数；窗口两两不重叠；两个独立窗口的间隔保持 8–12 s；
  这构成一对一匹配的强约束（一个窗口只能产出一个候选，一个候选只属于一个窗口）。
- **参考工具侧**（`tools/reverse-check/scan.mjs`）：**本轮未升级**为窗口区间一对一匹配，
  它仍在评测「旧算法镜像 vs 1 秒参考」。原因：Node 侧没有新内核的镜像，直接改匹配规则会与生产不一致。
  升级窗口匹配留到 2C-3（届时会把内核镜像同步到 Node，按区间重叠 + 一对一分配统计
  召回/拆分/合并/边界误差/bestUtc 误差）。

宿主机实测（ArkTS 单测内临时探针，已移除；上海 31.2304/121.4737，容差 3° 除非注明）：

| 场景 | position 调用 | 耗时 | 窗口数 | 无法判定区间 | 最大深度 |
|---|---|---|---|---|---|
| 1 天，容差 3° | 1 342 | 14 ms | 1 | 0 | 17 |
| 1 天，容差 0.05° | 773 | 8 ms | 1 | 0 | 17 |
| 1 天，容差 6° | 1 434 | 16 ms | 1 | 0 | 17 |
| 14 天，容差 3° | 15 838 | 167 ms | 11 | 0 | 17 |
| 365 天，容差 3° | 653 975 | 7 181 ms | 40 | 0 | 17 |
| 1 天，无命中（目标高度 89°） | 69 | 1 ms | 0 | 0 | — |

- 与旧算法对比：旧版 ≈380 次/日（2C-1，Node 镜像），新版 ≈1 300 次/日，约 **3.4 倍**；
- 2C-1 估算的 1 150 次/日偏乐观，实际 773–1 434 次（随容差变化），据实报告；
- `unresolvedIntervals` 在所有样本中为 0，最大深度 17（上限 18），说明分类没有退化成暴力扫描；
- **365 天 7.2 秒**（宿主机）意味着 2C-3 必须解决取消粒度与调度：目前仍是逐日同步调用。

## 10. 未能证明完备性的场景

1. 短于 1 秒的窗口仍可能漏（分辨率限制）；
2. 方位变化率上界 `0.05 °/s` 是经验保守值；在 |Δaz| > 30° 或高度 > 80° 时不使用上界而是强制细分，
   但**没有**对近天顶方位突变做形式化证明；
3. 高度变化率上界 0.0045 °/s 在极区、极昼/极夜边缘仍属估计，未做误差界推导；
4. 长窗口的 best 点用「≤200 点取样 + 黄金分割」近似，`cost` 在窗口内未必严格单峰；
5. 浮点边界：恰好等于容差的时刻可能因浮点误差落在窗口内外两侧（1 秒粒度内不可分辨）；
6. 逐格召回率（2C-1 的 36 目标网格）未复测；
7. 数学意义上的「零漏报」**未证明**，本文所有结论均为有限分辨率下的数值结果。

## 11. 2C-3 的接口需求与遗留任务

1. **取消与调度**：内核需要支持「按时间段让出主线程」的增量接口（例如 `searchWindowsChunked(..., deadlineMs)`），
   返回值携带 `done` 标志与已找到窗口；否则 365 天 7.2 s 期间取消只能等一天走完。
2. **参考工具升级**：把内核镜像同步到 `tools/reverse-check/scan.mjs`，实现窗口区间一对一匹配
   （召回/拆分/合并/边界误差/bestUtc 误差/调用量）。
3. **跨日 Top-K**：`ShootWindow` 已可跨日收集，需要全局去重（跨日界窗口）、模式 A（cost）与
   模式 B（时间分布）两种排序策略、以及全局配额替代逐日 `maxResults`。
4. **性能**：目标把 365 天压到可交互范围（例如穿越检测分层 + 缓存赤纬/均时差 + 必要时 Worker），
   并测设备端耗时。
5. **页面**：`ReversePage` 仍逐日调用并二次排序；2C-3 改为窗口驱动，进度按窗口/时间段而非「天」。
